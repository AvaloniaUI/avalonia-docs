## Remarks

Restoration uses a three-tier strategy:

1. Fast path: if the captured leaf is still attached to the live tree (true for every non-structural edit and for the pre-edit side of a just-replayed structural edit), re-derive the global offset as `Node.GlobalStartOffset + leafOffset`.
2. Path walk: when the captured leaf has been detached (structural Undo/Redo replaces node instances), walk the child-index path from the document root. `MaterializeFromSnapshot` preserves child ordering deterministically, so the path resolves to the correct rematerialized leaf.
3. Last-resort fallback: offset-based pointer creation.

The leaf offset is frozen at capture time because the leaf's
`GlobalStartOffset` may shift between capture and restore when
earlier content changes. At restore time the global offset is
re-derived from the (possibly replaced) leaf's current
`GlobalStartOffset` plus this captured `leafOffset`.
