### Cut Method

Cuts the current selection to the clipboard without waiting for the clipboard write.

```csharp
public void Cut()
```

#### Remarks

Await [Avalonia.Controls.Documents.Primitives.Components.TextEditorKeyboard.CutAsync](xref:Avalonia.Controls.Documents.Primitives.Components.TextEditorKeyboard.CutAsync) instead. The clipboard is a platform resource another
process can hold, so the write can fail after this method has already returned, and
a caller here cannot sequence anything after it.

</section>

#### Remarks

Delegates to [Avalonia.Controls.Documents.Primitives.Actions.EditorActions.Cut](xref:Avalonia.Controls.Documents.Primitives.Actions.EditorActions.Cut) so the keyboard shortcut and
toolbar/menu paths share one implementation, including the rich-format
(RTF) clipboard payload published by
[Avalonia.Controls.Documents.Primitives.Components.ClipboardOperations.CutAsync(Avalonia.Controls.TextSelection,Avalonia.Visual,System.Collections.Generic.IReadOnlyList&#123;Avalonia.Controls.Documents.Serialization.IDocumentSerializer&#125;,System.Threading.CancellationToken)](xref:Avalonia.Controls.Documents.Primitives.Components.ClipboardOperations.CutAsync%28Avalonia.Controls.TextSelection%2CAvalonia.Visual%2CSystem.Collections.Generic.IReadOnlyList%7BAvalonia.Controls.Documents.Serialization.IDocumentSerializer%7D%2CSystem.Threading.CancellationToken%29).
The clipboard is a platform resource another process can hold, so the cut can fail:
awaiting the returned task is how a caller sees that, and how it sequences work
after the clipboard write.
